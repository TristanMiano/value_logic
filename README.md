# Value Logic

Value Logic investigates reasoning with useful but fallible models without requiring direct access to final metaphysical truth. Its practical motivation is that a model can remain worth using within a domain, task, tolerance, and resource budget even after a more general theory supersedes it.

## Current formal direction

**Phase one is complete. Phase two now develops the value-based calculus first.** The active question is:

> What semantic objects and inference rules let an agent draw conclusions justified by preservation of pragmatic value, rather than merely attach scores to conventional judgments?

The authoritative roadmap is [TODO_v2.md](TODO_v2.md); start at its **Next task** pointer, not at the first unchecked item encountered in an older document. Read the [research protocol](v2/RESEARCH_PROTOCOL.md) before executing research work.

The new phase compares candidate foundations before choosing one. Scalars, intervals, contracts, partial orders, the phase-one license calculus, and particular neural architectures are possibilities, not immutable premises. Formal arguments remain relative to their declared mathematical assumptions. Value-first semantics is a research commitment, not a claim that fallibilism uniquely entails one calculus.

Work proceeds through derivation, literature, and executable testing, with evidence gates that can return the project to earlier definitions or proofs. The protocol requires prospective effort forecasts, actual clock records, minimum-duration work on selected tasks, and protected time for both reliable gains and uncertain, longer-term results.

## Working method

Use one selected task, repair task, or gate attempt per prompt unless the user explicitly requests a batch. A task may require several sessions; record partial progress rather than claiming a minimum duration or proof obligation has been satisfied. Consult the active repair queue before starting downstream work.

Keep derivations and equations as durable notes, literature checks as separate evidence, and executable tests with reproducible configurations. Preserve failed approaches and counterexamples. A gate passes on its specified evidence, not on elapsed time, a polished paper, or an agent's confidence.

Commit completed or explicitly partial work with its task ID after validation. Do not automatically push unless authorized. The September 19, 2026 roadmap revision was explicitly authorized for GitHub publication; it does not grant blanket authorization for future pushes.
