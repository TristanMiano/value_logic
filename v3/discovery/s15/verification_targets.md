Codex (GPT-6), October 23, 2026. DEVELOPMENT. No confirmation freeze,
promotion or numerical readiness forecast is made here. Each target is a
useful moderate-contribution event, not a requirement to solve all five questions.

## N15-P/v1: sharp small-information counterfactual envelopes

Establish the dimension-unrestricted sharp envelopes in
[norm_transport.md](norm_transport.md), [joint_target.md](joint_target.md)
and ONE clearly specified relative-scale or endpoint adapter, with an explicit
partial-receipt decision. It is acceptable to confirm a smaller coherent
theorem first; preserve the exact selected event/version when doing so.

The information contract contains an old scalar optimum, p and the normed
spaces' declared class, target normalization, and separately justified
operator/target-change bounds. It does not grant the old matrix or optimizer
to the receipt consumer. The delta sought is the optimal envelope conditioned
on that retained information and an implementable outward certificate.
Zero new operator calls in the final certificate does not make the original
receipt, change warrant or root calculation free.

Necessary evidence: fresh proof reconstruction, sharpness including limiting
versus attained endpoints, valid treatment of zero bounds/degenerate scales,
and one outward-arithmetic threshold example unavailable from a weaker
receipt. Compare the exact statement with quotient/graph norms, regularized
least squares, operator interpolation and Gram/moment optimization. A
same-information ordinary implementation ties. If an existing theorem plus
a routine substitution already supplies the complete contract, reassess the
claimed delta rather than rename it.

Cheapest falsifying screen: ask the closest primary formulation to recover
the exact one-dimensional optimization and its witnesses. This is more useful
than another large numerical parameter grid. Readiness: UNASSESSED.

## R15-C/v1: certified correction of a fallible polynomial model

Establish one complete service using [error_skeleton.md](error_skeleton.md),
a declared range-acquisition or [private-scope](private_scope.md) rule, and
an economical exact-anchor correction regime. Either acquisition route can
be selected; both are not required for a first useful contribution. Include
[feature repair](feature_repair.md) when finite input features permit it, so
the baseline also benefits from accumulated interpolation information.

The service must state what makes the truth/model error polynomial, how
degree and exact arithmetic are warranted, what the truth oracle exposes,
and which common event covers later adaptive uses. Partial probes retain
their frozen questions. Private checks must hide their points/sketches and
retire at the first rejection. A new statistical recompression and a proved
algebraic edit spend confidence differently.

The candidate's useful delta is turning a poor but structurally correctable
model into a cheaper bounded evaluator with an explicit common guarantee.
The current forecast example proves at least13.35499% fewer expected
full-vector probes than the declared fixed-theta baseline for rank4 in a
larger ambient space, with cap7 and false-completion probability<=.001.
This is an analytic comparison, not a full runtime invoice or a claim over
the best ordinary acquisition rule. The feature example uses1008 rather
than4480 exact coordinate outputs under its stated n128/M35/d4/k7 premises;
it is a component count, with ordinary two-sided interpolation as a tie.

Necessary comparisons: ordinary PIT, invariant discovery/POLYDEP, range
finding, CUR/interpolation, learned betting mixtures, direct factoring,
candidate-plus-holdout validation, and exact stopping at a known full rank.
Evaluate one realistic tariff including model evaluation, basis selection,
proof/degree acquisition, coefficient arithmetic, storage and truth batching.
If an aggregate oracle is used, price it separately from a coordinate query.

Cheapest falsifying screen: find whether the chosen true solver returns a
whole vector at essentially the same price as one coordinate, or whether
its public symbolic form already exposes the correction. Either can erase
the proposed saving. Generic learned-mixture safety is already in Halt Fast!;
generic low-rank correction is established. Moderate novelty of the evidence
and correction composition remains UNASSESSED.

## I15-Q/v1: query-count interfaces and the price of weakened purity

Establish [the three criteria](pure_query_criteria.md) under their precise
fresh-reset, count-only, padding and private-state contract. A focused useful
instance may use the seven-bit Hamming quantizer or balanced-weight family.
The target includes an explanation of why that observation restriction is
needed by a concrete bounded inference service. An artificial tariff alone
does not establish usefulness.

Separate any information, finite-horizon approximate identification and
almost-sure finite-mean zero-error identification. Distinguish per-tape,
per-episode distributional, conditional-history and whole-transcript purity.
The approximate-purity extension is a changed guarantee, with explicit
episode/information lower bounds; it is not a cap improvement at the old duty.
The cap6 Hamming decoder trades many episodes for a smaller cap and is not
a fee win over the earlier cap7 interface.

Necessary comparisons: randomized encodings, nonnegative literal degree,
randomized query complexity, postselection/zero-error query results, causal
cost coding and information channels. Include coefficient acquisition,
randomness generation, decoder/storage work and any observable timing.
The modest n8 stopping example saves6.83% of primitive queries but only
about.46% of the constructed fee at reset100; ordinary identical stopping
matches it. Neither is a new audit-stream result.

Cheapest falsifying screen: determine whether a natural client actually
requires this count-only disclosure rule and whether persistent private
coins/state are genuinely unavailable. If either changes, the claimed cap
may cease to be relevant. Readiness: UNASSESSED.

Implementation scope for N15-P/v1: an exact theorem for arbitrary real p
does not imply that an implementation can accept an arbitrary real number

an uncertified floating optimum. The current numerical probes establish
