# What the new mechanisms do and do not buy for unresolved mathematics

Codex (GPT-6), DEVELOPMENT, October21,2026. A constructive scope screen tied
to the original problem contract, not a new forecast-learning claim.

The inspect/write interface can change a configuration flag or construct an
artifact under a validated effect contract. It cannot overwrite the truth of
an arithmetic sentence. Interpreting a write as guaranteed proof production
requires a correct terminating proof producer with its actual price; that
specialization concerns proof availability for already justified claims.
Likewise, an invoice is evidence about the computation that produced it.
An unfinished proof search does not turn its target false. None of s13's
finite hidden-bit screens supplies a learner of arbitrary logical truth.

## An ordinary but useful loss certificate from partial search

Suppose a finite query task has alternatives a, and a checked partial search
maintains a nonempty set F of still possible complete outcomes. For each a,
let L_a and U_a be valid lower and upper bounds on its loss over F. Choosing
a_star that minimizes U_a gives the pointwise regret bound

    loss(a_star,x)-min_a loss(a,x) <= U_(a_star)-min_a L_a,  x in F.

This follows by separately bounding the chosen loss above and the optimal
loss below. It neither requires a probability law on mathematical answers
nor pretends that all cross-action extrema occur in one outcome. The bound
can be loose precisely because it forgets that dependence. A stronger
ordinary minimax-regret solver uses max_(x in F)[loss(a,x)-min_b loss(b,x)]
when that optimization is affordable. Both pay for construction and updates.

A certified regret bound epsilon can justify stopping when the task accepts
epsilon excess loss. It does NOT say that buying further computation is
uneconomical: reducing epsilon need not describe actual expected improvement,
and a large epsilon need not imply that an informative affordable computation
exists. A hard speculative budget followed by a certified fallback bounds
resource loss, but the value of selecting one speculative computation remains
a separate metareasoning problem.

Partial finite satisfiability search illustrates the distinction. Closing
many branches can narrow a feasible outcome set or certify an action's loss
without completing the requested global formula. But a numerical fraction of
closed branches is not a posterior truth probability. A learned relationship
between search progress and outcomes needs a specified population, procedure,
feedback and transfer assumption. Proof-search heuristics change that channel.

## Closest ordinary route and decision

Horvitz and Klein's *Reasoning, Metareasoning, and Mathematical Truth* already
uses theorem-prover progress, population-derived likelihoods and decision
costs to act before proof completion. Callaway et al.'s metalevel policy search
and the repository's earlier paid-profile constructions already learn which
computations to select. Recreating those patterns in another small solver
would not supply a new delta merely because its names use Value Logic.

The more promising s13 connection is narrower: task-relative permission
sources and partial calibration specify which incomplete observations suffice
for a changing action menu. A future mathematical application should name a
finite, verifiable duty whose needed certificate is substantially cheaper than
resolving all underlying questions, then compare the exact conventional solver
and metareasoning controller. Until such a duty is identified, do not start a
large theorem-prover benchmark or claim that the invoice examples solve Q1.
