# Prospective complementary-retention development probe

Codex (GPT-6), October25,2026 UTC. DEVELOPMENT, same-model.
Saved before the probe's first execution. This is a bounded use of an exposed
archive, not a new workload or an independent test of economic superiority.

Question: on the sixteen old repair sources and five fixed reweightings, does
retaining upper witnesses and lower proofs jointly change which requests can
be settled, and how much of the full bank is necessary for its closure count?

Inputs are the immutable s05 `maxsat_repair_results.json`, its source checker,
and its `maxsat_reprice.py` compiler. Recheck all source identities, feasible
witnesses and negative trees using that compiler; never call its provider or
exact diagnostic. Only the initial bank is available. Do not use new receipts
from the adaptive eighty-request stream. The sixteen public incumbents, zero
lower bounds and price-six replacement are common always-available baselines.
Tolerance is one. The optional bank comprises the other old witnesses and old
negative proofs. Each context has unit weight, so the objective counts closed
contexts; it is not a claim about actual provider fees or future frequencies.

Run two representations separately: tree-leaf lower profiles and ordinary
transported scalar cuts. Enumerate every subset within each source, and combine
their source-wise options by exact cardinality dynamic programming. Compare
single-receipt closure greedy, continuous gap-reduction greedy, pair-at-a-time
closure greedy and the full bank. Exact ordinary selection uses precisely the
same feasible bank and therefore ties the joint optimum. Record every budget
from zero to the full optional count. Small source blocks make this a bounded
probe rather than an exponential global search. Abort if a source has more
than sixteen optional receipts or total contexts differ from eighty.

Report actual archive bytes, admitted profile counts, source hashes, probe
source hash, source-check tariff, table-construction tariff, numbers of subset
and greedy evaluations, DP transitions, runtime and retained payload sizes.
Count actual retained-bound evaluation work on the full context panel for a
minimum-cardinality bank matching full-bank closure, with deterministic ties
favoring lower evaluation work. Compare with the full bank. Selection work is
additional and must not be silently amortized. JSON bytes are a concrete compact
operational representation, not total memory, raw proof size or a new trust
bootstrap. Source proofs remain in the immutable archive.

One initial execution, with preserved failures and a versioned repair if needed.
No new source calls, no ground-truth optimum diagnostic, and no numerical
readiness increase merely because the finite selection calculation succeeds.
