# One source-aware query-selection extension

Codex (GPT-6), DEVELOPMENT, declared after cr01 exposure. Preserve cr01's
negative result: only uf20-02 enables one new weight-at-most-two mask under
the fixed coordinates; the other five enable none. Both selected coordinates
are forced in all three 50-bit sources and in the singleton 20-bit source.
This limits what that screen says about useful query selection.

On the SAME six exposed sources, use exactly one ordinary deterministic
selector. Starting with the full saved source-model set, greedily select two
distinct variables minimizing the sum of squared sizes of the induced
partition cells. Tie-break by variable index. The second variable refines
the first partition. This is an unweighted model-splitting heuristic, NOT an
asserted source probability law. It does not inspect edit-menu sizes, objective
weights, future truth or solver performance. Record all scores and model-bit
inspection counts. No additional selector sweep is authorized by this plan.

Compile the same two-flip menus at all nine histories using the existing
direct and reuse SAT arms; compare every answer to universal source-model
checking. Retain the singleton source as an informative zero-information
boundary. Record both positive and negative menu changes.

Then construct one finite decision problem per source using these selected
coordinates: terminal zero costs zero; terminal one pays sum w_i*x_i on
signs, w_i=((5*i+3) mod 9)-4 for zero-based i; each flip costs 1/8 and each
queried fact costs 1/4. At most two flips and two distinct queries are allowed,
with total cap four. These two separate caps are part of the policy class;
do not call it the unrestricted cap-four model. The same class and certification
rule bind the comparator, including under point-source laws.

Include a third ablation that may query but retains only the root's initially
valid masks at every history. Keep the FULL comparator in all three objectives.
This separates the value of predicting cost from the value of enabling a new
revision menu. It is declared before either selection or optimizer output.

Build the source-independent private-history flow with a discrete option for
each valid mask and terminal zero. Optimize worst-case regret over the saved
source models, compare against the optimized no-query restriction, and repair
all choices onto a 2^20 grid. Check exact rational regret upper bounds and
bounded-dual lower bounds. Preserve source hashes, raw solver advice, repaired
policies, query usage, and all costs included in the objective. Numerical
solver limit is 45 seconds per arm; unchanged process retries remain bounded
as in cr01. Neither unpriced source preparation nor model-selection computation
becomes free because it is absent from this finite objective.

This is a targeted developmental repair of the first screen, not independent
confirmation. An ordinary optimizer with the same menus ties exactly. The
question is whether that finite costed capability is nontrivial on these
sources, not whether the construction beats conventional optimization.
