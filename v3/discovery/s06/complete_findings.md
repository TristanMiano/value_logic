## Relationship to the other s06 services

This run makes **complete direct branching purchases after full cost
calibration**. It imports shared utilities from the native adapter module but
does not instantiate or call a persistent native IHS engine. The
[native stream](native_findings.md) is a separate eighty-request supplied-weight
experiment with actual resident MiniSat/HiGHS state, objective/core reuse and a
separate checked negative-proof bridge. Those capabilities should not be
attributed to this full-calibration run.

The [joint service](joint_repair.py) instead interleaves cost observations and
native logical purchases while retaining a common uncertainty set. Its
acquisition policies and the full-calibration controller answer different
engineering questions. A fair resource comparison must give every arm the same
admitted receipts, compact evaluator, supported purchase menu, source
observations, warm state and tolerance, then charge each arm's own purchases
and unresolved attempts. This result establishes a usable fallback and a
reconstructable completion contract. It does not establish that full calibration,
targeted acquisition or either logical backend has the lowest total cost.
