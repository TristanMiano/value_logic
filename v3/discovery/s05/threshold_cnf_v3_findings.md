# Fixed-tree pruning protects continuation while sharpening the source

Contributor: **ChatGPT (GPT-6 Astra Pro)**. October 12, 2026 UTC.
DEVELOPMENT; the previously exposed cohort is replayed, with no new sampling
or confirmation claim. [Implementation](threshold_cnf_v3.py),
[invoices and traces](threshold_cnf_v3_results.json),
[unchanged v2](threshold_cnf_v2_findings.md).

The constructive result is a safe way to use additional proof consequences:
retain the original decision tree and let the new receipts discharge its
entailed tests. This keeps the original decisions while acquiring a sharper
reusable threshold source. It removes the observed midpoint re-centering
premium. Extra certificate production and adapter work remain paid.

## A pathwise theorem that needs no source law

Fix a source instance x and a finite correct binary query tree T. Its internal
nodes request definite predicates; checked answers select children and leaves
return the target feature. Additional receipts are sound consequences about
this same immutable source. At each node, the enhanced executor either buys
the original query or follows its entailed answer without buying it. The
executor does not change the tree in response to extra information.

**Theorem.** The enhanced executor visits the same nodes and branches as the
original execution on x, buys a subsequence of the original tests, and returns
the same target feature. If each original test has a nonnegative,
history-independent price c(q,x), its test expenditure cannot increase:

```text
sum over purchased original tests c(q,x)
    <= sum over all tests on the original path c(q,x).
```

The proof is induction along the original path. A checked purchase returns
the instance's answer. A sound receipt entails that same answer. Either case
selects the same child, so pruning removes expenditure without introducing a
different original test. This holds for adaptively arriving receipts as well
as initial side information. Prices may vary arbitrarily with source and
query; the controller need not know them, and they need not be functions of H.

The theorem separates two bills. Producing extra certificates, checking
entailment, retaining traces and compiling the protected tree have their own
explicit costs. These are an additive allowance, not a guaranteed saving.
Net expenditure improves only when avoided original work exceeds that
allowance. If c consists only of upper bounds, the inequality compares the
corresponding expenditure ceilings; it does not by itself order two realized
invoices. An unresolved purchase selects no child and retains its exact
continuation and already incurred bill.

For a stateful engine, the subsequence and output results still hold, but the
price conclusion needs more. A skipped query might have produced a witness,
learned clause or warm solver state making a later query cheap. For example,
two successive tests can cost 1 and 1 when the first leaves helpful state;
skipping the first from a bare truth receipt can make the second cost 100.
Truth entailment alone does not preserve all useful computational artifacts.
This is why the theorem's pricing qualification is substantive.

## A stronger native-provider statement for this restricted adapter

There is also a useful equality result for the present service. Assume both
executions start with the same receipts and retain all raw witnesses and
proofs; native calls receive only the immutable current formula and equal
caps, with deterministic, stateless behavior. Before calling native, both
adapters exhaustively try their retained SAT assignments and UNSAT transports.
Saturation creates only checked consequences and aliases of witnesses already
retained; it creates no new raw witness or negative proof.

Under a fixed original query path, **native purchase sequences are identical**.
Inductively, both executions have the same raw witness set and checked negative
proof capabilities before each original node. If saturation prunes a new SAT
node, a witness shared with the ordinary bank already satisfies its formula;
the ordinary exhaustive transport would also settle it without a native call.
If a node needs native in either execution, the shared proof capabilities
cannot settle it in the other either. Both call native on the same formula
and cap, receive the same checked result, and preserve the induction. Aliases
may change how many checks are attempted; they do not change which retained
raw assignments exist. Previously checked negative answers are shared along
the same original path.

This equality does not extend automatically to eviction, restricted witness
search, solver seeding, learned clauses, global budget stopping based on the
different adapter bills, or negative-proof extraction beyond the shared
interface. It also does not equate adapter or process costs. The ordinary
control here already receives exhaustive proof reuse; saturation exposes its
positive consequences earlier and more broadly.

## Fixed rule and source-bound replay

The v3 rule was announced before this replay. A per-row shadow interval stores
only the answers encountered on the original tree. The endpoint rule, full
midpoint tree and minimax query-count tree are compiled from that shadow
state. A stronger saturated interval can prune a node; it cannot re-center a
midpoint or replace the chosen subtree. New request stages use shadow state
again. Known endpoints are normalized out in both services. Every compared
method receives the same paid tree admission, guard and trace machinery.

The unchanged public CNF recipe, seed and sixteen replacement draws are taken
from v1. There are thirteen distinct sampled identities, each with eight
nested formulas. Repeated identities reuse receipts while retaining their
draw multiplicities. Neither the controller nor the tree compiler receives
the diagnostic exact H values or supplied query prices. Minimax weights of
one mean query count only. Tree construction is timed; its internal planning
arithmetic remains outside the declared operation tariff, as in v1.

| Original query rule | Native calls, either service | Native units, either service | Ordinary total units | Saturated total units | Newly pruned tests |
|---|---:|---:|---:|---:|---:|
| Endpoint bank | 25 | 1,492,469 | 1,720,504 | 1,767,099 | 10 |
| Full midpoint threshold | 31 | 2,009,909 | 2,256,243 | 2,303,059 | 11 |
| Minimax query count | 25 | 1,492,469 | 1,720,540 | 1,767,135 | 10 |

For all three rules, the complete native trace—row, query, checked answer,
witness and invoice—matches both its ordinary v3 control and original v1.
All original visited query paths and requested feature answers also match.

Fixed-tree midpoint removes the v2 saturation/re-centering premium of
**274,683 native units**: its bill returns from 2,284,592 to 2,009,909. On the
previously diagnostic row 41, the tree still asks 5 after SAT at 3, even when
the witness also settles 4. It no longer substitutes the more expensive
sequence through 6 merely because saturation narrowed the interval.

The extra saturation adapter bills are 46,595 units for endpoint and minimax,
and 46,816 for midpoint: about 2.71%, 2.71% and 2.07% of their respective
ordinary total invoices. The common v3 protection itself adds 4,675, 5,506
and 7,438 units over the original ordinary implementations, respectively.
The table includes all these charges. No native solve is saved by the newly
pruned tests in this cohort; each was already available to ordinary witness
transport. Recorded process times are one-run observations, not a speed
comparison: roughly 0.35–0.48 seconds per arm, with planning below 1.5 ms.

## The acquired value source is still sharper

For endpoint and minimax, the richer interval source survives fixed-tree
protection:

| Completed request stage | Ordinary mean H-interval width | Saturated mean H-interval width |
|---|---:|---:|
| Pair `(3,4)` | 39/16 = 2.4375 | 25/16 = 1.5625 |
| Add `(1,6)` | 13/16 = 0.8125 | 3/8 = 0.3750 |
| Add `(0,7)` | 7/16 = 0.4375 | 3/8 = 0.3750 |

The first-stage reduction is 35.9% at identical native expenditure. Each
saturated arm retains fourteen extra SAT receipts. Full midpoint already
identifies H exactly, so its final CDF source has no remaining censoring to
sharpen. This identifies where paying for saturation can have future value:
partially queried rows retained for subsequent features and changing stakes.

There is a structural guarantee behind this measurement. Fixed-tree execution
retains all original node answers and may add sound consequences, so each
enhanced H interval is contained in its ordinary shadow interval. The
empirical CDF lower counts can only rise and upper counts can only fall.
Summing their normalized gap over integer thresholds gives exactly the mean
interval width, because a row contributes at exactly u-l thresholds. Applying
the same fixed-sample confidence allowance preserves this pointwise narrowing;
it neither creates additional samples nor reduces the allowance for sampling
uncertainty. See the [calibration interface](threshold_calibration.md).

Thus source sharpening and query-price protection can coexist without
inventing a probability law or cost forecast. Whether the sharper source
repays its adapter preparation across later decisions remains open. The
[canonical-frontier analysis](saturated_frontier.md) gives a concrete next
implementation route: avoid repeated witness scans and combine clause-delta
preparation with the original source verification, while retaining this fixed
tree as a comparison policy.

## Bounded verification

The saved result includes 1,485 finite abstract rollouts over the original
trees, all nine possible thresholds and every tighter sound initial interval.
Their paths, outputs and nonnegative stateless price inequalities agree. This
is an implementation screen; the induction establishes the general result.
A capped checked purchase retains the same pending subtree and unchanged
shadow/actual interval while recording its spent work. All source runs finish
with exact requested features and no unresolved continuations.

Post-run checks verified 27 source-hash references across v1, v2 and v3; both
earlier result hashes remain unchanged. Another 1,184 interval enclosures were
checked against already purchased diagnostic H values, including actual and
shadow node states. Every failed witness extension leaves the interval
unchanged, and every pruned node has zero native calls and native units.
