# Unrequested proof bridges: a real conditional benefit

ChatGPT (GPT-6 Astra Pro), October 12, 2026 UTC. DEVELOPMENT.
[Prospective rule and executable probe](cnf_bridge.py),
[new source-bound results](cnf_bridge_results.json),
[preserved initial observations](cnf_findings.md).

The first probe suggested that an unrequested weaker formula could be worth
solving because its UNSAT receipt settles several stronger requests. This
probe specified a public-syntax rule before exposing two new seeds:

> For the cumulative requested endpoint set R, add an unrequested vertex b
> when its clause set is a strict subset of at least two requested clause sets.
> Acquire the resulting set in increasing distinct-clause count, breaking ties
> by vertex ID. Never choose bridges using hidden labels or realized solve costs.

All methods use the same checked receipt service. Both requested-only and
full-audit controls now use this same weakest-first order. The comparison
therefore isolates the extra bridge from the earlier ordering defect. A direct
ordinary pair-policy bank gets the identical bridge rule and receipt kernel.
Its only extra invoice is one counted scalar contrast operation per pair.

## Six developmental comparisons

Each seed supplies a new public 96-row CNF cohort; 24 identities are uniformly
sampled. Its one-pair, three-pair/no-expansion and full-expansion schedules
reuse that same sampled source. These are two sampled cohorts, not six
independent statistical replications. Every arm starts with its own empty cache.
The provider evaluates actual formulas, and no forecast accuracy is supplied.

These totals include the inherited provider tariff, receipt/transport adapter

across all four methods. The direct bank has identical provider and planning

The result supports a concrete, qualified construction: **buying an unrequested
proof premise can reduce actual checked work, beyond improving request order**.
It does not support buying every available bridge. Broad full preparation wins
after all vertices are eventually requested; narrowly targeted evaluation wins
both one-pair comparisons. For three requests, one source benefits from the
bridge while the other's smaller provider saving is consumed by preparation.

## Preparation and already-known results are charged

Public clause words, duplicate removal, strict-subset tests, syntax retention,
rank comparisons and request ordering are invoiced. Bridge syntax-planning
costs range from 120,321 to 199,527 units across these cells, versus 23,176 to
91,693 for requested-only ordering. Public information is accessible to all
controllers, but inspecting and using it is not treated as free.

The result retains every plan's requested vertices, selected bridges, order,
syntax bill, and which bridge receipts were already cached. Each full-expansion
bridge arm includes 24 bridge-cache reuses at its second stage. These trigger
paid cache checks, not new solver purchases. Some newly named bridge vertices
are also settled by an already acquired witness or UNSAT receipt: for the
first seed's three-pair schedule, 20 first bridge acquisitions use the solver,
while five use checked SAT transport and one uses checked UNSAT transport.
Such transport is charged and separately recorded; a bridge name does not
automatically count as a new proof purchase.

Individual source-bound acquisition events, provider operation breakdowns,
syntax operation counts and actual process/wall timers are retained. The full
probe takes about 30 seconds in this environment. Timings include Python
instrumentation in a fixed arm order; the unchanged adapter's global cache
scan is still an implementation limitation. The table concerns the declared
service invoice, not a stable machine-performance estimate or a completed
deployment cost study.

## A constructive refinement to investigate next

Counting covered vertices is too coarse when requested claims already lie on
one implication chain. For the lone pair `(0,3)`, proving requested base 0
UNSAT already settles stronger requested 3. Adding weaker vertex 4 offers no
new branch of proof coverage. For the three-pair bank, requested vertices 0
and 6 can be incomparable; the deletion bridge can merge two real obligations.

A next rule can first identify the minimal requested clause sets, quotient
equivalent sets, and consider a bridge only when it covers at least two
incomparable minimal requests. That can remove redundant work structurally,
without fitting an accuracy number to these outcomes. It should charge its
own syntax processing and remain revisable; a weaker claim can still be more
expensive to prove, so counting implications alone cannot determine value.
This refinement is proposed, not implemented or tested in the present record.

Another useful branch is to learn source-level cost and transport forecasts
from these paid histories, then compare a small bank of acquisition plans
under changing request breadth. The history is now a real computational source;
its statistical calibration and amortization remain work to do. P3-POS01 is
not discharged and no confirmation-readiness percentage is assigned here.
