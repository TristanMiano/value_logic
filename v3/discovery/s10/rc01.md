# rc01: finite retained-certificate development screen

**Prospective; Codex (GPT-6), October 14, 2026.**

Before a paid request service, implement a small standalone integer checker in
JavaScript and freeze its executed version. Avoid native solver dependence for
this diagnostic. Use explicit CNF inputs with positive cost-feature variables:
paths, triangles/cliques, mixed-width hyperedges, split clauses with auxiliary
pivots, planted mixed-polarity formulas and a source whose zero feature vector
is feasible. Include n=3..8 and deterministic seeds. The bounded extractor sees
only the actual clauses and feature map, not a generator classification.

Extract existing positive feature clauses and width-at-most-four resolvents,
with caps of 256 derived clauses and 50,000 examined parent/pivot candidates.
Log any cap or missing consequence. Independent checking reconstructs each
resolution step and every feature cover. Use an ordinary greedy nonnegative
integer packing proposal; its multiplier feasibility for the initial objective
is a proposal-quality choice, not needed for later slack-corrected validity.

Enumerate small source models only as explicitly billed diagnostic work. Choose
up to three declared deterministic models as a repeated supplied action. Check
all endpoint boxes for n<=4 and 128 seeded interval states for larger sources,
all retained bound inequalities against exact induced-objective optimization,
and single-coordinate additive audit reductions. For the smallest models,
also reconstruct regret directly over compatible box corners. This is finite
support evidence, not a polynomial completeness result.

Compare capped convolution with direct response enumeration for blocks of up
to four coordinates. Check scalar-only transport, retained-dual improvement,
and nonnegative-zero fallback bounds separately. Reject changed source, feature
map, proof pivot, cut, multiplier and out-of-box receipt controls. No actual
cost purchases or complete-service calls occur in rc01. Save setup, diagnostic
arithmetic and representation sizes separately; unknown runtime costs stay
unknown. Only after this screen decide whether a paid service is justified.
