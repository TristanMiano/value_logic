# Reusing a selected checked answer without changing the statistical path

Contributor: **ChatGPT (GPT-6 Astra Pro)**, October 10, 2026.
**P3-08 DEVELOPMENT**, prospective design and coupling argument.

## 1. Why this is a separate variant

The first integrated broker buys a fresh cold checked answer at its selected
position in every block, even when the exact same source/version/program was
checked earlier. This preserves the accepted physical purchase path but can
repeat unnecessary computation. The ordinary combination already admits
checked cache reuse. We now distinguish the *selected receipt schedule* from
the physical cold computations which supply those receipts.

This does not authorize dropping a selected receipt, changing the selected
position, changing its propensity, reallocating an unused quota position,
updating on additional labels or choosing an action-dependent cache policy.
It changes the paid implementation of the same deterministic checked service.
The complete older broker and all common-v1/v2 records remain unchanged.

## 2. Coupling and exact transfer

Fix one admitted deterministic exogenous query tape, expert library, contract
and complete selector/action bit string. Compare two initially empty service
instances under sufficient all-path budgets:

1. the existing cold provider;
2. an owned provider which performs a paid full-key current-version cache
   lookup at each selected call, checks a retained receipt on a hit, and
   otherwise makes the same cold checked purchase and pays to retain it.

The adapter's cache contains only previously admitted successful receipts
from that deterministic provider. Its lookup is independent of the sampled
terminal action, and its key includes the complete interpretation and source
versions and mathematical input. New request IDs receive newly bound local
receipts. Each compared episode uses a fresh provider instance, so an epoch
withdrawal is never followed by reuse of a previous instance's authority.

**Coupling lemma.** The two completed runs have the same base forecasts,
selected positions, propensities, purchased bits, weight updates, action-bit
consumption, live hard masks and terminal answers. Proof is induction over
the requests. Initially the numerical and hard states agree. At a selected
position, a checked hit and a successful cold call return the same fixed
truth bit for the full key. A miss runs the same sound cold provider. Either
way the broker receives exactly one current selected receipt, and performs
the same hard admission and numerical update. At an unselected position,
identical state and bits give identical issuance and action. Cache eviction
can affect future bills but cannot change a successfully checked bit.

The induction compares mathematical/output paths, not provider identities,
invoice operation lists, physical call counts, remaining balances or partial
failure paths. The adapter has its own source/provider version. The unchanged
broker binds that actual version rather than pretending the receipt came
directly from the cold provider.

As a result, the accepted fixed-expert expectation statements and the
base/live/snapshot confidence constructions apply to this completed selector
path under the same fair-bit, deterministic-tape, soundness and predictability
premises. There is one successful *selected service receipt* per block.
No theorem about the number of new observations or physical cold purchases
is asserted. The adapter's actual paid invoice replaces the cold invoice;
all-path funding must use its own conservative envelope. A completed cheap
seed cannot establish that envelope. Failed service work still has no
successful-receipt guarantee.

## 3. Finite paid adapter and envelope

The adapter reuses the existing exact CNF cache, with capacity at most64,
and can prospectively select linear or hashed indexing. It has no free
prepopulation. The cache's initialization, full input validation, lookup,
collision verification, storage, eviction and rebound receipt are already
priced operations. Cold child work is reserved, absorbed exactly once and
checked before its answer is released. The adapter prepays a bounded final
local receipt and small state/control records before any cache lookup.

All admitted keys have at most343 words (use512 conservatively in this
envelope). A cache operation's two input-validation passes, initialization,
complete collision scans across64 entries, digest/bucket work, rebound
output and a full atomic eviction/insertion fit below eighty thousand units
at the conservative512-word envelope when both lookup and insertion are
required. The initial v1 bound was below sixty thousand at the actual343-word
key maximum; the independent reconstruction retained the512-word bound.
The adapter uses the deliberately
loose **131,072-unit** overhead allowance in addition to the cold provider's
existing public `service_cap(query, solver)`. It covers the cold child
reservation as well as all adapter work; it is not an observed mean fee.
The initial independent source reviews reconstructed this allowance; the
v1.1 response-prepayment amendment retains the same conservative cap.

Every fresh episode pays source procurement separately. The current v1.1
direct service admits integer accounts of at least576 units, validates their
ordinary meter bounds, and prepays its conservative576-word response as the
first paid operation. Below-minimum rejection is external admission
instrumentation and admits no provider work. Every later admitted denial
returns a paid no-answer receipt and retains its spent prefix. Invoice JSON
serialization is external measurement. The original v1 early-output denial
and successful comparisons are preserved in their own source closures.
Cache initialization/commit is atomic under its existing tariff.
The controller stops on a failed selected receipt, and the cache instance is
not reused for a later episode. Internal test/audit serialization is external
measurement work, not additional policy information or an unpriced deployed
certificate.
