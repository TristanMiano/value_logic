# P3-08 prospective integration design v1 — DEVELOPMENT

Contributor: ChatGPT (GPT-6 Astra Pro), 2026-10-10 UTC.
This is a development design, not a P3-09 challenge freeze. Existing option-A
results and sources remain unchanged.

## Selected service and formal bridge

Use a generic, explicitly versioned port of the accepted fixed-mass product
learner, retaining its numeric normalization and finite supplied-bit API.
The new finite program family is SAT of a fully specified bounded CNF program:
there exists an input among the finite Boolean assignments on which every
clause evaluates true. The mathematical answer is deterministic. Public seeds
select inputs, not stochastic truth. Source-visible simplification, exhaustive
search, DPLL, exact reuse and precomputation remain ordinary alternatives.

The broker owns each sampled position, its actual propensity, the exact local
pending issue, the selected provider call and its returned checked receipt.
It issues a base q and a current output q before receiving that round's new
answer. Both are immutable. Only one selected receipt per complete block
updates the shadow learner, at block end. All action bits are consumed even
where hard answers determine the action. Hard answers never replace expert
feedback or change a scheduled purchase. This can knowingly repurchase an
already known answer; the strongest ordinary combination may use a separately
scoped purchase policy that skips such work.

A live hard-answer store binds the entire semantic query content, source and
semantics versions, and a broker epoch. Request IDs separately bind a specific
purchase. A sound current answer immediately fixes its hard coordinate and
subsequent current readouts; the old base forecast remains a separately typed
historical statistical state. New same-block knowledge can correct subsequent
outputs, but it must not be inserted into the base sampling certificate.

For every actual fixed query answer y, a sound correction replaces q by y and
an action by y. Thus emitted Brier and actual terminal error weakly decrease
pointwise under the same base purchase, update and action-bit path. The base
upper expectation/episode bounds therefore transfer with the additional paid
work. Base lower bounds do not transfer. No direct shared-residual identity is
claimed for outputs changed by same-block receipt information.

Fresh complete epochs reset the finite learner and invalidate old hard warrants.
Per-epoch bounds may be reported under their separate events; they are not
silently a simultaneous multi-epoch confidence claim. Mid-block scope change
or missing/invalid purchased receipt aborts the successful-quota contract.
Prior costs and immutable completed outputs survive; no missing label is
scored or used as an update.

## Decisive counterexample to a tempting alternative

Take B=2, the same false claim twice, base q=(1/4,1/4), and a uniform selector.
If the first selected answer immediately masks later q and one naively uses
the frozen-mask centered estimator, J=1 gives mask (0,1), V=0, U=-1/4;
J=2 gives mask (0,0), V=U=1/4. The residual mean is 1/8, not zero.
Sound hard answers alone do not preserve the martingale proof. The retained
base upper-bound route handles both histories without that invalid step.

## Development comparison design

Primary implementation rows: accepted finite hybrid, uncorrected finite online
mixture, ordinary probability-to-expected-cost, proof/evaluation-only, charged
exact computation, exact cache, and a credible ordinary combination. A free
oracle is evaluation-only and excluded from deployable cost rankings. The
ordinary combination may reuse the same learned components; equality is a
valid result, and best-per-instance hindsight selection is an oracle diagnostic.

Use both a common fixed-feedback replay comparison and autonomous paid policy
comparisons. These answer different questions. Report pre-resolution Brier,
all-issued Brier, terminal mistakes, checked answers, cache use, aborted/missing
outputs and full resource vectors, separating cold setup from ongoing work.
Fixed-record price sensitivity is a linear rescore, not a rerun of a
price-sensitive selector or an acquired future-performance law.

A separate finite structural arm reconstructs ordinary repair on the same
sources, actions and all tied optima, including paired-support counterpossibles.
Its interpreter-operation tariff is named separately; units from different
arm tariffs are never added or compared directly. Source-wise repair keeps
unresolved source cases outside the minimization and holds receiving actions
fixed across them. Stale/withdrawn reports cannot retain active applicability.

All method source closures, public inputs and commands are saved with each
version before its development execution. Failed versions and exposed outputs
remain preserved. The last stage computes private labels after policy outputs
close and records its own procurement cost; policies cannot read those results.

## Resource contract

Learning/program services use declared 64-bit word and operation tariffs,
including input and code setup, expert evaluation, solver/checker work,
randomness, controller arithmetic, retained hard answers, reads and output.
These are abstract priced units, not measured CPU cycles or Python heap bytes.
Physical time and peak resource observations are separate. A child call has
a funded cap and returns its actual spent invoice on success or failure.
Output/cleanup is reserved. Capacity failure produces a typed outcome, retains
sunk work and does not receive the complete-success learning guarantee.

No claim of general logical induction, calibration, coherent joint truth
probabilities, optimal value of computation, generic SAT hardness or economic
superiority is licensed by this design. The intended gain is a working joined
interface and a discriminating scoped comparison.
