## Conclusion

The current ordinary controls suffice for the bounded **negative economic
conclusion about these recorded candidate executions**. They do not establish
an optimal value-of-computation controller or a complete algorithmic frontier.
An optional-only controller would be a meaningful stronger ordinary method,
but adding it cannot reverse the already observed absence of a candidate
advantage over the supplied ordinary controls. It is unnecessary to delay
P3-08 completion for another broad sweep. Name the present combination a
**fixed-exploration heuristic** and retain this limitation explicitly.

On all five declared price points in all three v2 cohorts, the minimum
empirical-mean terminal objective belongs to ordinary methods. This is a
retrospective comparison of whole recorded policies, not an executable
private-truth selector. The common cold-source bill is 48,274 units per run,
so it cancels in comparisons within the common-v2 cohort/service. Source
procurement and optional report charges must remain separately visible.

## Fixed records, active prices, and online updates

For a completed fixed transcript, use

\[
J(\alpha,\beta,\lambda)
=\alpha\,\mathrm{FP}+\beta\,\mathrm{FN}
+\lambda(C_{\mathrm{local}}+C_{\mathrm{source}}).
\]

An optional reporting service adds its own declared source and execution
cost. Keep whole-episode quantities together, or divide every term by the
same horizon. A 128-query error total cannot be compared to a 64-query rate.

Changing the prices on an unchanged transcript is **repricing**. The current
ordinary combination uses lambda during execution to decide optional
acquisition. Each lambda-specific run has its own paid answers, cache state,
cost history, and potentially later numerical forecasts. A native-price
comparison uses the combo actually run at that evaluation price. The lower
envelope over all previously run lambda settings is a separate retrospective
best-recorded-policy benchmark. It is neither a new deployable selector nor
a second independent random trial.

Common_v2 restarts each policy from fresh state and pays its online updates;
it does not inherit a freely trained v1 state. However, implementation choices
were informed by v1 development outcomes, and the query tapes and seeds were
reused. This is post-inspection development re-execution, with no held-out or
prospective-coverage claim. Three seed records support reported arithmetic
means and paired implementation checks, not a statistical population claim.

## What the objective columns do and do not establish

Issued Brier loss measures the earlier frozen probability. Terminal error
measures the binary action after the allowed paid computation. For v1
`cold_mixed`, exact DPLL has zero terminal errors while its half forecasts
produce Brier 16. The ordinary probability controller has mean terminal
errors 31/3, compared with 16 for the finite uniform learner, despite slightly
worse mean issued Brier. Their same numeric seed does not match feedback
positions: the ordinary controller consumes a selector-only bit tape.
Thus neither that terminal difference nor the Brier ordering isolates the
readout rule by itself.

The no-computation endpoints deliberately share a half forecast while emitting
different supplied actions. They make no checked-truth claim. Exact caching
can improve early Brier through previously purchased same-key answers without
any numerical model update. Keep early probability, current hard knowledge,
and terminal utility separate. A general claim about the best attainable
forecast service would additionally require an explicit earlier deadline and
the same permitted pre-issuance computation for all competitors.

## Exploration floor and remaining ordinary opportunity

`ordinary_combo` buys a full checked DPLL answer at every designated selected
position whose answer is not already cached. That branch ignores lambda.
The optional branches use fallible public/own-history estimates, but this
selected branch is an explicit exploration floor. At sufficiently high
resource prices the finite possible error reduction cannot pay for that
extra computation compared with a fixed action. The v2 no-computation arms
make this endpoint executable rather than an uncharged oracle.

Also, the optional branch's fee estimate concerns provider work. Acquisition
control, receipt checks, cache insertion, and later updates still appear in
the actual bill. A child-provider maximum fee is not a maximum for the whole
incremental controller operation. This does not invalidate the recorded
invoices, but it rules out describing the heuristic as exact marginal VOC
optimization. The selected cost estimates and acquisition opportunities are
fallible by design.

An **optional-only** method would remove the forced selected call, retain the
same library/cache/checked shortcuts, compare modeled error against paid
cost information, and update only on its own acquired or retained labels.
It would exploit cheap useful queries while declining expensive ones, which
neither fixed endpoint can do. It would retain modeling/decision overhead,
could acquire too little information, and would inherit no selective-feedback
quota theorem. This is a substantive future competitor if a claim about
optimal acquisition or the strongest possible frontier is intended.

It is not load-bearing for the present negative conclusion. On v2 mean
records, `value_uniform_hashed` is directly dominated by `probability_cost`
on cold_mixed, hashed exact caching on repeat_online, and linear exact caching
on cheap_structure. The hashed ticket candidate is similarly dominated on
cold_mixed and cheap_structure. For repeat_online its mean pair is
`(errors, local units) = (28, 3753542/3)`. To beat hashed exact caching
`(0,1874485)` requires

\[
\lambda\ge 84/1869913\approx 4.49219\times10^{-5},
\]

while beating either no-computation endpoint `(64,28944)` requires

\[
\lambda\le54/1833355\approx2.94542\times10^{-5}.
\]

Those intervals are disjoint. This establishes a retrospective ordinary
envelope below that mean candidate record for every nonnegative lambda;
it does not prescribe a truth-informed switching policy for unseen inputs.

## Minimal asymmetric-stakes extension, if desired

The existing focused evidence already checks the integer readout against
exact rational costs and includes an eight-row asymmetric `(FP,FN)=(3,1)`
execution. A new broad asymmetric sweep is unnecessary for validating the
algebra. If a new behavioral arm is desired, use one already declared public
tape, a single declared seed, and lambda in `{0,1/10000}`, with both supplied
stake orientations. Rerun `probability_cost` and the same named combination
under each orientation; the eight executions constitute a small declared
development witness rather than a coverage study. Reprice existing exact,
fixed-action, and price-insensitive broker records separately.

To isolate asymmetry from overall stakes, use `(FP,FN)=(1/2,3/2)` and
`(3/2,1/2)`, keeping the mean stake equal to the symmetric unit-stake case.
Equivalently pass raw `(1,3)/(3,1)` with **unit_price = 2 lambda**, then divide
the whole objective by two. Normalizing only the reported errors after a
raw-price run would double the policy's willingness to compute and confound
the experiment. The greedy thresholds are q greater than 1/4 and 3/4,
respectively. For the probability-only policy, the own selector and label path
remain price-independent, giving a clean within-policy readout comparison.
For the combination, acquisition and later paid updates can change, so a full
new execution is required; an old trajectory cannot be relabeled as adapted.
