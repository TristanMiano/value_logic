## 3. Consequences for the proposed implementation

The review found four distinctions requiring explicit implementation treatment.

**Outer coverage versus finite coherence.** After adding a constraint, an old
frontier can still cover the new feasible set while containing assignments
that violate the new constraint. Its robust enclosure may remain sound, but
an arbitrary distribution on it need not obey all new constraints. Output
types must distinguish these services. The U04 status for newly accepted
signed evidence also needs its own next-eligible-update rule.

**Transactional publication versus incomplete mutation.** Every published
frontier, loss enclosure and dependency cache must have a stated validity
invariant. A partially updated internal structure cannot be treated as a
completed certificate because the caller's budget expired. A preserved valid
snapshot, atomic new result, or typed pending/stale response can implement the
required boundary.

**Withdrawal versus addition.** Deleting a premise can restore assignments
that earlier pruning removed. Invalidating a cached bound is necessary when
its dependency disappears, but reconstruction, restoration or a valid broad
fallback is still needed to answer again. Previously computed warrants remain
historical records. A task-independent reset is sound when properly charged;
task-specific transport can sometimes avoid a reset.

**Settled old queries versus new-query prediction.** The source note gives a
receipt-only stream in which every fixed query resolves while every current
query is still unresolved. A convergence statement must name its quantifiers,
retention and cumulative-resource assumptions. Pattern extraction remains a
separately implemented and charged procedure available to both comparators.
