## 1. Question and common receiving obligation

The accepted P3-05 resource comparison left an interface difference: an ordinary
ADD produced an exact answer inside its own process, whereas the portfolio
produced a separately checked current certificate. This recurrence supplies a
finite ordinary proof interface and charges its delivery. The earlier observed
ADD advantages remain valid for their earlier interface and source revisions.

Let a validated current frame contain Boolean coordinates, hard expressions,
positive rational soft weights in one rank tier, a rational loss difference,
and its complete interpretation, request, loss and unit record. A caller supplies
a feasible complete incumbent and a requested rational upper bound. Write
$`r_F(x)`$ for the current weighted rank, $`w`$ for that incumbent, and
$`c=r_F(w)`$. The receiving domain is

```math
Q_F(w)=\{x\in\{0,1\}^n:\ \bigwedge_{h\in H_F}h(x)=1,
\quad r_F(x)\le c\}.
```

The service independently verifies the incumbent and certifies

```math
Q_F(w)\ne\varnothing,\qquad
\forall x\in Q_F(w),\quad D_F(x)\le B.
```

Rank ties and every nonoptimal point within the incumbent sublevel are included.
Neither a bound on only the optimizing repairs nor an empty-domain implication
satisfies this service. The bound and incumbent are shared inputs; this experiment
does not claim to measure their acquisition or optimize the requested bound.

The trusted boundary is a finite exact interpreter, a separately implemented
receiver, and caller-owned process state. Evidence is inert, bounded JSON. The
caller supplies the expected source record, current record, coordinate epoch,
order, incumbent, bound and unique request identifier independently of the proof.
A source digest binds the selected bytes; it is not a claim that arbitrary
process memory or a malicious host has been authenticated.

## 2. A constructive ordinary DAG bridge

The ordinary producer retains ordered algebraic decision diagrams and exports
three kinds of facts: node definitions, justified pointwise Apply results, and
expression-to-root bindings. All references are backward references to facts
already admitted in the same epoch or earlier in the current packet.

**Node induction.** A rational terminal denotes its stated constant. A decision
node on coordinate $`i`$ denotes its checked low or high child according to that
coordinate. The receiver verifies exact types, bounds, acyclicity and the fixed
variable order. Reduction and unique nodes improve representation; their
canonicalization is not permission to trust a claimed operation result.

**Operation induction.** A checked Apply fact denotes the named operation on
its two input functions. The receiver recomputes terminal arithmetic and every
permitted identity or absorbing-element shortcut. In the recursive case it
checks the earliest tested coordinate, both cofactor dependencies and the
corresponding reduced result. Already admitted facts are unconditional
denotational equalities. The induction is over their dependency order, not an
assumption that the producer ran its own Apply implementation correctly.

**Input linkage.** Bottom-up expression bindings must agree with the receiver's
actual finite grammar and the required child or operation facts. Literal, bit,
negation and constant-scale rules are checked explicitly. The receiver constructs
the current hard conjunction, weighted rank, loss difference and threshold tests
from independently supplied input. A perfectly valid diagram for a substituted
expression does not pass that linkage check.

The decisive diagram is the current violation indicator:

```math
V_F(x)=\left(\bigwedge_{h\in H_F}h(x)\right)
\mathbin{\wedge}[r_F(x)\le r_F(w)]
\mathbin{\wedge}[D_F(x)>B].
```

If the independently linked and checked root for $`V_F`$ is zero, the node and
operation inductions imply the requested universal bound. The separate incumbent
check proves nonemptiness. This is a finite soundness argument for the stated
rules. It is neither a formal verification of the Python implementation nor a
generic native v2 proof compiler.

### 2.1 Edits, retained facts and evidence delivery

A resident receiver may reuse checked unconditional node, Apply and expression
facts. A delta must match the admitted base counts, source, coordinate epoch,
bit count and order; its references are interpreted against the receiver's
actual owned facts. There is no cryptographic digest of the complete prefix.
Every request still checks the full current record,
incumbent, bound and newly reconstructed violation goal. A conditional old-domain
bound is never admitted as an unconditional expression identity.

Admission uses immutable chunks and a final state swap. The enclosing paid service
works on a fork and publishes it only after all checking, retention serialization
and terminal delivery succeed. A new unique request identifier makes the previous
current receipt stale. A failed fork does not invalidate the mathematical
truth of previously checked unconditional facts, but it cannot return an older
receipt as the new bound. The measured wrapper conservatively evicts all
producer and recipient scientific caches after every failed attempt.

A fresh recipient has no previously checked facts. Even a warm producer must
send a full proof to it. The first implementation sends all retained facts;
the separate post-primary-exposure dependency-pruning control charges extraction
and retains the full manager. It is an additional measured ordinary control,
with no claim that its extracted proof is globally minimal.

The implemented fragment inherits one rank tier, at most ten bits, exact input
rationals and expression bounds. The new wire additionally caps computed rational
components at 4,096 bits, below the old ADD's 16,384-bit cap. Unsupported values
and exhausted proof limits are paid failures to deliver; they do not establish
that the requested mathematical bound is false.

### 2.2 Which logical implication is sufficient?

The exact diagram construction is one sufficient bridge. More generally, let
$`V`$ be the actual violation predicate and let $`Z`$ be an independently
checked Boolean predicate. If the receiver establishes both
$`V(x)\Rightarrow Z(x)`$ for every assignment and $`Z\equiv0`$, then the
requested universal bound follows. Exact equivalence of every intermediate
expression is stronger than this final implication requirement.

An ordinary SAT refutation can also suffice. A checked encoding of the actual
violation query, followed by satisfiability-preserving proof steps ending in
contradiction, rules out actual violations. Fresh acyclic definitional variables
must be linked to the input; a proof about an independently substituted formula
does not establish the intended query. This explains why proof-producing BDD
SAT methods are relevant comparators without requiring them to export a full
model-counting equivalence certificate.

It is different to preserve only satisfiability of the **domain** before
checking a loss. For a one-bit example take $`Q=\{0,1\}`$, $`D(b)=b`$,
$`w=0`$ and $`B=0`$. Replacing $`Q`$ by $`Q'=\{0\}`$ preserves nonemptiness
and the supplied incumbent. The claimed bound holds on $`Q'`$ and fails on
$`Q`$. Thus an equisatisfiable domain replacement can hide a violating tied
minimizer. This does not undermine equisatisfiable refutation of the complete
violation query; the location of the preservation guarantee matters.

### 2.3 Conditional lemmas and unconditional meanings

An old domain warrant states an implication, for example
$`H_{\rm old}(x)\wedge[r_{\rm old}(x)\le c_{\rm old}]
\Rightarrow[D_{\rm old}(x)\le B_{\rm old}]`$.
This whole implication can remain true after a new request arrives. Using it
still requires discharging its antecedent or a valid transported version.
It does not make $`D_{\rm old}(x)\le B_{\rm old}`$ true everywhere. In
contrast, a checked expression binding states the denotation of that expression
on every Boolean assignment in the fixed coordinate/interpreter environment.
Such a binding may be reused after changing hard constraints and ranks.

For the measured service, induction over successful deliveries gives the
following restricted operational theorem. Suppose the caller maintains the
declared source, coordinate environment and independent request inputs, starts
with an empty or previously validated receiver, and uses fresh request IDs.
Every published `CURRENT_BOUND_CERTIFIED` receipt then has the service of §1,
conditional on correctness of the checked rules and their implementation.
New node, Apply and expression admissions preserve the denotational invariants;
reconstructing the current goal and checking the incumbent proves the current
claim; the final paid publication step is the only way to expose that claim.
An unsuccessful attempt publishes no current certificate. Its retained cost
and cache eviction concern availability and economics, not the truth of a
previously proved implication.

Equal base counts alone are not a claim of identical history. A packet from a
different same-length history must still justify each new fact under the actual
recipient ledger. It either passes those checks and proves the current claim,
or fails to deliver. A prefix-content hash could improve provenance and early
mismatch diagnosis; it is not a missing premise in this denotational induction.

**An empty delta does not have constant receiving cost.** Consider repeated
delivery of the same valid zero-loss frame with new unique request identifiers.
After the first full admission, the producer can send no new node, Apply or
expression rows. Nevertheless `_View.next_state` appends a new immutable chunk
after each successful receipt, and `Receiver.receive` appends the request ID.
With $`t`$ prior receipts, the pending unique table is empty. The lookup of the
zero terminal in the current-goal check visits all $`t`$ chunks before finding
that terminal in the first chunk. This is exactly $`t`$ resident-chunk probes
for that lookup, even though the set of mathematical facts has not grown.

The exported retained-state record also contains every empty chunk and request
identifier. Its length is at least linear in the number of receipts; request-ID
membership and tuple copying provide further history-dependent work. In a
cap-relaxed version with $`O(\log(t+2))`$-length fresh identifiers, constant
scientific facts would permit $`O(t\log(t+2))`$ history bytes, rather than
constant storage. This statement concerns that explicit history policy, not an
information-theoretic necessity for every sound recipient. A verified
compaction or reset policy is a possible different implementation.

The deployed receiver allows 256 receipts in one epoch and rejects the next
admission before checking its wire. The existing focused receiver audit already
checks that boundary. The paid wrapper evicts scientific state after a failed
attempt, so a later request can rebuild a fresh receiver; this is not a promise
of uninterrupted delivery or free rebuilding. This retained-history limitation
is separate from the fresh-recipient polynomial checking argument below.

## 3. What the inherited tree receiver can require

For $`n\ge2`$, form forward- and reverse-associated XOR folds over the same bits.
Set $`D`$ to their difference, omit hard and soft rows, and request $`B=0`$.
The difference is identically zero on the whole cube.

On every non-singleton box, each fold has interval $`[0,1]`$. The two distinct
syntactic nonlinear features do not cancel in the inherited collector, leaving
upper bound one. There is no hard or rank exclusion. Thus every accepted
`BandProof` leaf fixes every coordinate. Any binary split proof then has exactly
$`2^n`$ leaves and $`2^{n+1}-1`$ visited nodes, for any valid split order.

The same conclusion holds for a fresh `PortfolioProof` with `choices=()` under
all its allowed current-row multipliers. After stripping outer negations, the
collector retains two distinct equality features with coefficients +1 and -1.
The available nonzero contextual premises concern assigned coordinates alone;
their residuals evaluate to zero on that cell and cannot cancel those features.
Every proper box therefore still has conditional upper bound one.

The complete rule-by-rule derivation is in the independent
[tree obstruction review](../work_logs/R_P3_B_B_2026-10-10_S1/reviews/literature_and_obstruction/tree_obstruction.md).
The executable caps permit instances through ten bits and 2,047 tree nodes.
The asymptotic statement concerns the explicitly uncapped rule schema. An
admitted full-domain lemma can yield one-leaf reuse; richer algebraic rules and
shared DAG certificates are outside this lower bound.

Under a fixed order, a parity diagram has linear representation size and both
folds reduce to the same root. This does not make construction, intermediate
nodes, proof export or receiving checks free. The experiment records all of them;
it does not infer a linear total bill from the size of the final zero root.

### 3.1 The complete shared evidence has a polynomial-size construction

There is a stronger statement than compactness of the final parity root.
Consider the same forward/reverse XOR grammar, an empty initial manager and
any fixed complete variable order. Use the producer's memoized pointwise Apply
and its cache-insertion evidence trace. Ignore the finite implementation caps
only when discussing this explicit rule schema. Assume source and request
metadata do not contain an unrelated growing payload.

At a fold step involving $`j`$ variables, the previous parity diagram has
$`O(j)`$ reachable nodes and the newly added bit has three nodes. Apply for
equality has at most their product many distinct operand pairs. Complementing
the result applies subtraction from the constant one and also has $`O(j)`$
pairs. Each processed pair contributes at most one fact and one newly allocated
decision node, in addition to a fixed small terminal set. Across both folds,
the sum of these bounds is $`O(\sum_{j=1}^n j)=O(n^2)`$.
Final constant scaling has $`O(n)`$ pairs; even the general product bound for
the final addition is $`O(n^2)`$. The empty hard/rank goal adds only a constant
number of operations. The recording mechanism therefore has $`O(n^2)`$ node
and Apply rows and $`O(n)`$ expression bindings for this family.

This count includes intermediate parity functions and the evidence linking
the two syntactic folds. Numeric node IDs and variable indices need
$`O(\log n)`$ digits. The complete serialized key of a prefix expression has
$`O(n\log n)`$ bytes, so retaining all $`O(n)`$ expression keys contributes
$`O(n^2\log n)`$ bytes. Node/operation rows have the same aggregate upper
order. The witness, order and ordinary input record fit within that bound.
Consequently this family admits full independently checked shared evidence of
$`O(n^2\log n)`$ encoded size under the stated schema and metadata convention.

This is an upper bound for this concrete representation/construction together
with the receiver-specific tree lower bound. It is not a generic polynomial
compiler claim. It does not treat hash lookup, repeated parsing, arbitrary
rational arithmetic or serialization as unit-cost physical operations. Nor
does its asymptotic order assert a byte advantage at any particular admitted
small dimension: headers and expression keys can outweigh tree records there.

### 3.2 Complete fresh verification also has a polynomial work bound

For this same no-hard/no-soft parity family, the full receiving computation
does not expand the shared trace into a tree. During one fresh admission the
old chunk list is empty. Each node row checks a constant number of child IDs;
each nonterminal Apply row looks up two already checked cofactor facts and
the justified result node. `_operation_result` never recursively recomputes
Apply. One final state commit creates a single chunk, and its serialization
keeps numeric references rather than substituting child graphs at every use.

Let $`L`$ include the full packet and independently supplied current/source
records, order, witness and identifiers. Let $`B`$ bound input and terminal
rational component sizes. The cutoff here is zero and the hard/soft loops are
empty, so a terminal equation uses at most two $`B`$-bit rational operands;
unreduced products and sums have $`2B+O(1)`$ bits. This last premise would not
bound general incumbent-rank prefix arithmetic and is not claimed for it.

Assume exact arithmetic, numeric hashing and decimal conversion on
$`O(w)`$-bit operands cost at most $`O((w+1)^3)`$, at most quadratic JSON
parsing/encoding work in the examined text with arithmetic separately charged,
and at most quadratic total map probes over a linear number of
stored entries and operations. This permits collisions and charges full key
comparison. With $`w=B+\lceil\log_2(L+2)\rceil+1`$, a deliberately loose bound is

```math
T_{\rm fresh}(L,B)=O\!\left((L+1)^3(w+1)^3\right).
```

Repeated expression parsing is included. If the complete written keys have
lengths $`k_i`$, their sum is $`O(L)`$. Even quadratic work per key is bounded
by $`\sum_i k_i^2\le(\sum_i k_i)^2=O(L^2)`$. Each parsed row subsequently
performs only a constant number of ledger operations; it does not recursively
readmit all descendant bindings. The retained state is a constant multiplicity
of the written facts, keys and current record.

For the constructed parity packets, $`L=O(n^2\log(n+2))`$ and $`B=O(1)`$,
so this yields a conservative $`O(n^6\log^6(n+2))`$ bit-work upper bound.
The exponent is not a measured performance prediction or a tight bound. Actual
program-file enrollment adds its separately counted bytes; they are fixed for
the named closure. The [full reconstruction](../work_logs/R_P3_B_B_2026-10-10_S1/reviews/literature_and_obstruction/fresh_receiver_work_bound.md)
states the primitive, owned-data, source-size and stack assumptions and derives
the arithmetic allowance. The principal reconstructed its local-check and
written-key reasoning and retained the parity-only restriction.

This strengthens the complete evidence-size construction with an algorithmic
fresh-checking result under named hypotheses. It does not change any deployed
cap, establish arbitrary-dimensional Python execution, charge producer
compilation to the receiver, or assert a physical speed advantage. In particular,
it does not contradict the retained-history cost in §2.3.

### 3.3 Construction and export do not hide a forced tree expansion

The same source inspection covers a further possible gap: a polynomial packet
could, in principle, be produced only after exponential unrecorded search.
That is not forced by the recording construction on this particular parity
family. Let $`A,N,E`$ count its stored Apply facts, nodes and expression
bindings, and let $`S`$ be the expanded input syntax size. Each uncached
nonterminal Apply call makes at most two recursive calls. Their variable level
strictly increases; a pending normalized operation/operand key cannot be revisited through its
own descendants. Sequential evaluation finishes and stores the first child
before checking the second. Every distinct `(operator, left ID, right ID)` key,
normalized for the declared commutative operators, is therefore computed at most
once, and total Apply invocations are bounded by the top-level calls plus
twice the number of recursive cache misses.

There are $`O(S)`$ top-level expression-operation calls and $`O(A+S)`$ total
Apply invocations. The overridden `RecordingManager.apply` and `.compile`
only save and restore the work-counter context. `_RecordingDict.__setitem__`
checks a fresh key, stores it and appends one proof fact; it does not rescan
all earlier facts. Node/terminal creation has at most a constant number of
table operations per relevant call. Expanded expression tuple hashing and
equality can reread whole prefixes, and their byte/occurrence cost must be
counted, but each such key has size at most the explicitly included syntax.

`export_dag` traverses the stored node and proof logs, writes the complete
expression keys and validates the resulting immutable evidence. The separate
`to_wire` call performs final JSON encoding.
Its validation rereads each written key a fixed number of times. The producer
live-state record writes nodes/unique entries, cache/log entries and expression
keys with constant multiplicity. Children remain numeric IDs. None of these
steps invokes `export_tree`, which intentionally targets the older tree
language, or searches all assignments. On this true parity family the
counterexample branch is not taken.

Thus construction, full export and one complete producer live-state period
are polynomial in $`S,A,N,E`$, the full written key/metadata length and the
stated arithmetic/map/text primitive costs. The bounds of §3.1 make all those
parameters polynomial in $`n`$ for this family. Together with §3.2, the complete
ordinary construction-to-fresh-receipt route has a polynomial algorithmic
upper bound under those conditions, including separately counted source bytes.
The inherited empty-history tree receiver still has an exponential visited
size and hence an exponential output/traversal cost under a tariff charging
a fixed positive charge for those visits or explicit serialized nodes.

This is an asymptotic comparison of the named cap-relaxed rule schemas, with
sufficient resources to complete them. It does not say that the fixed deployed
$`2^{27}`$ budget works for arbitrary $`n`$, that arbitrary ADD inputs compile
in polynomial time, or that a native portfolio with useful admitted history
has the same fresh-tree lower bound. It also does not overturn the finite
primary observation that direct checking is cheaper than either route.

## 4. Complementary domains and the strongest ordinary control

To avoid a constant-loss-only illustration, use two coordinates $`p,q`$ and a
separate block $`z`$. Let $`A(z),B(z)`$ be the two parity folds and set

```math
D=p-q+A-B,\qquad
H=(\neg p\wedge A)\vee(q\wedge\neg A).
```

The old domains $`\neg p`$ and $`q`$ each support bound zero. The current hard
domain contains points with $`p=q=0,A=1`$, which require the first domain, and
points with $`p=q=1,A=0`$, which require the second. It also contains
$`p=0,q=1`$, where the loss is -1. The loss is therefore nonconstant and neither
old domain alone covers the current request.

Each edit reserves a parity coordinate absent from extra hard and rank rows.
Flipping that coordinate preserves rank and other feasibility while realizing
both exclusive parity branches. The supplied incumbent has $`p=0,q=1`$.
Merely leaving a parity coordinate free in the hard constraints would not suffice:
rank rows could otherwise remove both exclusive branches from its sublevel.

A five-node cover splits first on $`p`$ and then, when needed, on $`q`$:
reuse the first domain at $`p=0`$, exclude $`p=1,q=0`$ by current hardness,
and reuse the second at $`p=q=1`$. All old certificate construction and admission
costs remain part of the bill.

An ordinary implementation is allowed to use exactly this portfolio kernel.
In particular, a newly checked ADD certificate can justify an old domain before
the same cover handles edits. The adapter must perform actual independent ADD
receipt verification and check its full frame, cutoff, bound and source; an
arbitrary report dictionary is not an admission. Any successful hybrid is an
ordinary comparator as well as evidence that the receiving kernel is reusable.

These old-domain objects are sound conditional warrants inside a supplied
finite interpretation. Their complementary applicability demonstrates a need
for both warrants in this particular reuse-only cover. It does not establish
that two fallible empirical models outperform an ordinary reasoner, that two
models are needed by every algorithm, or that the diagrams require the old
portfolio at all. Directly proving the current bound remains admissible.

## 5. Cost and usefulness contract

The prospective experimental contract is recorded separately before benchmark
execution. It includes constant overhead, parity reassociation and two sizes of
the nonconstant complementary-domain family, each with six versioned requests.
Resident and fresh recipients are distinct service conditions. Fresh tree proofs,
ordinary cold and warm DAG proofs, ordinary direct exact checking and the hybrid
ordinary/portfolio route are admissible controls. Legacy ADD-to-tree export is a
representation diagnostic, not the only ordinary option.

The bill includes source enrollment under a declared program-byte tariff, old
proof construction, producer work after every edit, proof encoding and output,
receiver input and checking, current receipt output and serialized retained
state periods. A live period occurs at each old-certificate admission and
current delivery, before cold/fresh state is discarded. Post-disposal retained
sizes are a separately reported observer diagnostic, not another charged period
at the same boundary and not elapsed byte-time. The producer's unique table, operation cache, expression keys,
proof facts and receiver state are included. Serialized state is a disclosed
accounting representation, not a measurement of Python heap size.

The finite tariff observes worker Python opcode events and bounded native C-call
events in CPython 3.12.14, plus declared byte and ownership events. It excludes
the measuring apparatus itself. Its caps make the native operations bounded;
one such event is not a hardware cycle or a claim to count each arithmetic bit
operation. Raw category vectors accompany every scalar bill. Results concern
this source revision and tariff, with physical CPU and heap claims excluded.

Consumer budget thresholds and the total-cost comparison are fixed before data.
For repeated verified requests, report exact cumulative differences and the first
and sustained crossing within the observed six-request horizon. A failure to
deliver is not ranked as a cheap successful certificate. No result is extrapolated
to an unobserved infinite horizon or optimized external ADD implementation.

The first source enrollment prepays the declared program and hash capacities
plus one bounded length-probe byte for each file before opening it. A missing,
overlong or mismatched file retains those capacity charges. Enrollment occurs
once per stream; a fresh recipient starts without scientific evidence, while
the installed interpreter is common infrastructure. Current-request preparation
is included in total cost even where it is outside the named consumer account.
An observed consumer bill $`u\le T`$ is descriptive affordability. Following
the same successful path under an enforced consumer account also requires the
protected failure capacity, $`u+1024\le T`$; no low-budget execution is inferred
merely by relabeling an already completed high-budget run.

### 5.1 What the exact price vectors establish

For a completed successful request, pool the invoice by cost category, retaining
the counts of opcode events, bounded native calls, proof/input bytes, live
serialized byte periods and ownership events. If two accumulated vectors
$`e,p`$ obey $`e_j\le p_j`$ in every coordinate, then

```math
\sum_j a_j e_j\le\sum_j a_jp_j\qquad\text{for every }a_j\ge0.
```

This follows by summing the nonnegative quantities $`a_j(p_j-e_j)`$.
The inequality is strict precisely when some strictly smaller coordinate
has positive price. It is a fixed-invoice statement. It does not authorize
replacing measured traces, changing a governor, assigning arbitrary prices
to different stages of the same category, or assuming completed service at
a different execution budget.

In the primary run, ordinary direct checking weakly dominates portfolio reuse
in this coordinatewise sense at **all six observed cumulative prefixes in
each of the eight stream/recipient cells**. Thus the observed absence of a
strict reuse saving is robust to every fixed nonnegative pooled-category
price vector over those recorded prefixes. Three individual requests fail
coordinatewise dominance: parity with a resident recipient at requests 2,

the ordinary arm. Every other pooled category remains no larger there; all

prevent a universal requestwise or time-varying-price conclusion.

A different price question distinguishes consumer from nonconsumer work.
Write $`a_m=C_m-u_m`$ for a method's fixed nonconsumer bill and $`u_m`$ for
its declared consumer bill. Holding its completed path fixed gives

```math
C_m(\rho)=a_m+\rho u_m,\qquad\rho\ge0.
```

This intercept includes request preparation and coordination, not only
stages named `producer`. In seven primary cells direct checking is the
unique cheapest line for every $`\rho\ge0`$. For the larger complementary
stream with a resident recipient, the two frontier lines are

```math
C_{\rm ENUM}(\rho)=345252+4672413\rho,
\qquad
C_{\rm warmADD}(\rho)=2901347+3436019\rho.
```

They tie exactly at $`\rho=2556095/1236394`$; ENUM wins below it and warm
ADD above it. Portfolio reuse never reaches the frontier, including ties:
one ordinary line has strictly smaller nonconsumer and consumer coordinates
in every cell. For this last cell, warm ADD saves 3,058,900 nonconsumer units
and 506,982 consumer units against reuse. These claims concern the six fixed
methods, not a globally optimal ordinary algorithm. Exact intersections,
all method lines, every request vector and every prefix are retained in the

### 5.2 Output pruning and retained computation have different costs

The additional ordinary control computes a dependency closure from the full
warm export, retains required node/Apply/expression dependencies, and renumbers
them consistently for a fresh recipient. The unchanged receiver still checks
the complete current linkage. Pruning does not add an inference rule or make
the producer's selected facts authoritative. Nor does a smaller output imply
a smaller producer state: the measured control keeps the entire warm manager,
constructs the full export, performs the closure/remapping work, then discards
temporary indices after emitting the smaller packet.

In its separate four-stream run, the 24 current packets shrink in aggregate
from 200,861 to 182,318 bytes. Consumer work falls from 18,310,960 to 16,341,407
units. The explicitly charged pruning stage costs 8,795,761 units and the
other stages save 2,008,415; the net total therefore rises by 6,787,346 units.
Every individual total bill is larger. Each stream's first packet has the
same size and three more consumer units; later packets reduce consumer cost.
All four six-request consumer aggregates improve, but direct ordinary checking
still has the smallest total bill and remains the sole ordinary-inclusive
frontier for the same consumer-price family in that fresh-recipient run.

The correct interpretation is conditional: output pruning can relieve a
recipient bottleneck while costing more total work. It is not the minimum
proof closure, a producer-memory compactor, or an optimal policy for selecting
which proof to send. A changed network/consumer price or a new retention policy
would require its own declared objective and, for execution claims, funded
work. The existing pruned packet cursor also cannot be applied to the original
warm manager's unpruned IDs; this control only sends full proofs to fresh
recipients.

### 5.3 Comparing funded paths with different delivered requests

When a fixed consumer account can stop an attempt, the observed primary bill
is not a complete description of the later state. A denied request evicts
scientific caches. A subsequent resident proof may need to rebuild its old
warrants; a subsequent full warm export may instead become smaller because
unused history was removed. Source installation that completed before the
failure remains installed. The separate capped run therefore preserves the
whole issued sequence rather than deleting failed requests from a cost average.

For a fixed stream/recipient prefix, let $`S_m`$ be the exact set of request
identities successfully delivered by method $`m`$, and let $`C_m`$ be the sum
of **all** its attempt bills, including failures. An equal-service cost ordering
is available when $`S_a=S_b`$. A useful more general partial order is

```math
S_a\supseteq S_b,\qquad C_a\le C_b,
```

with at least one strict relation for strict dominance. Equal success counts
alone do not imply the same delivered service: the missing request identities
can differ. A zero-delivery path remains a failure to provide the requested
certificates even if its invoice is smaller.

There is an exact limited utility interpretation. Suppose each issued request
$`i`$ has an arbitrary nonnegative value $`v_i`$ for its correctly delivered
certificate, with additive gross value, and normalize the resource price to
one in this declared tariff. Let

```math
U_m(v)=\sum_{i\in S_m}v_i-C_m.
```

Then $`U_a(v)\ge U_b(v)`$ for **every** $`v\ge0`$ if and only if the two
partial-order inequalities hold. Sufficiency follows by subtraction. For
necessity, use $`v=0`$ to require $`C_a\le C_b`$. If some $`j\in S_b\setminus
S_a`$ exists, assign that coordinate a value larger than
$`\max(0,C_b-C_a)+1`$ and all others zero; method $`b`$ then has greater
utility. A strict coverage advantage need not make utility strictly greater
when the additional certificates have zero value, whereas a strict cost saving
does so for every such value vector.

This characterization licenses a robust comparison of the fixed delivered
sets without selecting favorable values after exposure. It does not estimate
those values, assign independent value to certificates whose uses interact,
or prove that the method is an optimal adaptive proof policy. Under a hard
requirement to deliver every requested claim, any incomplete set still fails
that requirement; partial-order dominance is not a substitute for completeness.
The [actual-cap interpretation plan](../work_logs/R_P3_B_B_2026-10-10_S1/development/consumer_cap_interpretation_v1.md)
and observer analysis keep those distinctions explicit.
