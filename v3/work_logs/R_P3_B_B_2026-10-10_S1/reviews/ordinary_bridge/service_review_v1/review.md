## 2. Exact service and native codec

The derivation fixes the complete current frame, supplied feasible incumbent,
rank cutoff derived from that incumbent, and requested bound. The certified
domain is the entire current incumbent sublevel. Rank ties and nonoptimal points
inside that sublevel are included. A bound on only an optimizer, an empty-domain
implication, or an old current receipt does not meet the contract. The derivation
correctly distinguishes this bound service from selecting an optimizer or
acquiring the supplied witness and bound.

`frame_from_record` reconstructs the inherited request and frame types, checks
their semantic versions, and compares the entire canonical reconstructed record.
The packet parser rejects duplicate keys, inexact numbers and oversized or deeply
nested packets. `portfolio_from_wire` restores immutable tuples and exact
rationals and preserves choices, substitutions, witness, bound and proof tree.
The resulting object is passed to the unchanged portfolio verifier. Similarly,
`band_from_wire` reconstructs a native old band and `admit_band` actually verifies
it. Serialized cache inventories are diagnostic records, not authority to restore
an admitted domain.

The earlier native path checked the proof's witness but did not bind it to the
independently supplied witness. Equal rank alone was insufficient when the
supplied witness was infeasible. This was independently found by the receiver
reviewer, who owns the targeted boundary diagnostic. In v4, `native_receipt`
requires the exact supplied witness and exact rational bound before calling the
old verifier. `common_report` also checks the actual supplied witness's
feasibility and recomputes its cutoff. This closes that native/full-wire service
gap at the reviewed source. No new native checker rule was inserted into an old
file.

The ADD path separately binds the source record, order, epoch, current frame,
witness, bound and owner request identifier. Its receiver verifies node,
operation and expression facts before accepting the linked zero violation root.
The adapter invokes that actual independent receiver on a fork, corroborates
the newly committed receipt, checks the complete service fields, and creates a
fresh typed portfolio domain. It accepts neither arbitrary report dictionaries
nor raw private-cache insertions. After admission, both bootstrap routes call
the same `PortfolioCache.build` and `verify` implementation with the same
replacement maps. The focused frozen producer smoke separately established
identical subsequent proof and report records on its small native/hybrid case;
this review adds no execution of that comparison.

## 4. Live periods, retained state and hybrid disposal

The adopted finite convention is clean: one declared live-state byte period at
each successful old-domain admission and current delivery. Serialize before
disposal. Report post-disposal retained bytes separately, without pricing a
second copy at the same boundary. Surviving objects appear in the next delivery
snapshot. There is no invented storage interval after request six. These are
named event-boundary serialization proxies, not elapsed byte-time or a Python
heap peak.

The producer's state inventory includes its nodes, Boolean flags, order and
positions, actual unique keys, Apply cache and proof log, and expression cache
and proof log. The receiver includes admitted chunks, actual unique keys,
Boolean flags, Apply/expression mappings, source/order binding, all admitted
request identifiers, receipt JSON and attempt metadata. Thus neither side is
accounted only by final root or node JSON. Repeated references in named tables
are deliberately serialized as stated by the proxy.

For each hybrid old-domain admission, the wrapper pays an intermediate producer
ADD snapshot, an intermediate independent-checker snapshot, and portfolio state.
Those temporary diagrams are local variables. The adapter's resulting domain
contains only frame, cutoff, bound and provenance kind, so dropping the local
manager and receiver does not leave an implicit diagram inside the portfolio
cache. The recipient repeats checked admission from packets, pays its temporary
checker snapshots, and then keeps only verified portfolio domains when resident.
The diagram does not continue to earn uncharged authority after being discarded.

**Remaining v4 bootstrap-period mismatch.** Amendment 1 explicitly includes the
current packet and input at every bootstrap admission period. The current
delivery snapshots do include these objects on each applicable side. However,
`_bootstrap_receiver` snapshots only its checked ADD state and portfolio domain
record; it does not include the current `old_request` and `packet` in that
bootstrap period. The producer's bootstrap portfolio snapshot includes old frame
records and proof packets, but not the complete old request containing the
supplied witness. Their input/output byte events are charged; the omission is
specifically in the additional live-period representation.

The narrow correction is to include those existing complete request and packet
bytes in both native and hybrid bootstrap snapshots. Alternatively, declare
bootstrap periods to contain admitted scientific tables only and explicitly
distinguish them from current-delivery snapshots. Either choice must be recorded
before its affected comparison and preserve any already executed source. This
finding was sent to root as soon as identified. No primary result is inferred
from it, and it is not a mathematical soundness objection.

The invoice's historically named `retained_proxy_bytes` and
`max_retained_serialized_bytes` now refer to the meter's live-period snapshots.
Use the explicit post-disposal output fields for actual retained proxy reporting,
or clarify those invoice names in the analysis. They are not heap measurements.

## 5. Practical consumer budgets and finite conclusions

Consumer units include `receiver_*`, terminal and failure-terminal stages, and
the shared source enrollment. Enrollment is paid once per stream. A fresh
recipient has no previously verified facts but shares the installed interpreter
and selected program; it does not mean reinstalling software at every request.
The consumer bill includes old-certificate replay when that recipient requires
it, current request/proof input, independent checking, live state serialization
and current receipt output. Producer search is separately visible in the total
bill. The fixed thresholds are per-request observed bill thresholds, not a
single six-request allowance or a hardware running-time promise.

The service governor reserves 1,024 units for failure. Consequently, an observed
successful consumer bill $`u`$ with $`u\le T`$ is not by itself evidence that a new
execution with consumer cap $`T`$ succeeds: the governor normally requires
$`u+1024\le T`$. Keep retrospective bill thresholds distinct from actual
low-budget interruption probes, or report the reserve-adjusted feasibility
predicate. The receiver reviewer owns the focused reserve diagnostic. This
review does not rerun a budget counterfactual.

The whole-state eviction rule on denied or invalid requests is conservative but
coherent. It clears any interrupted mutable producer log together with retained
authority and the current receipt. Previously paid work remains paid. New
request identifiers prevent a stale receipt from answering a new request.

The useful conclusions remain finite and source-bound: exact checked service,
its observed complete category bills, and cumulative crossings within the six
requests. The parity tree obstruction concerns the inherited tree rule schema;
it is not a lower bound on shared ordinary certificates. The proposed results
cannot establish minimum ordinary cost, physical CPU or heap bounds, generic
malicious-host integrity, or an infinite-horizon break-even theorem. A closed
run should load one immutable source closure in a fresh process, since canonical
Python loader names intentionally preserve class identity rather than support
mixing several source revisions in one interpreter.
