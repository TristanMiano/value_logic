## 2. Runtime commands and retry interpretation

The primary launch uses a CPython 3.12.x interpreter with NumPy 2.3.5 already
installed. From the repository root, set the environment **before** Python:

```bash
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
python -m v2.experiments.freeze verify
python -m v2.experiments.runner prepare --task F15 --out v2/work_logs/F15_v1_run1
python -m v2.experiments.runner evaluate --task F15 --out v2/work_logs/F15_v1_run1
```

Actual interpreter provenance, stdout/stderr and native exit status belong in
the principal launch records. CPython/NumPy version equality is the declared
runtime contract; the protocol does not promise bitwise identity across builds
or hosts. File/configuration hashes and saved data digests support the narrower
reproduction claim.

The one unchanged retry uses the same primary output directory and stage,
with `--retry-unexplained` and a concrete `--failure-note`. An exclusive
`<stage>_attempt_2` directory prevents a third attempt. The retry checks the
original freeze, checks the original preparation-manifest binding for
evaluation, reuses complete hash-checked first-attempt units, and preserves
incomplete files. Discovery cannot restart after `evaluation_start.json`;
completed stages cannot run again through this directory.

Failure classification remains an operator obligation: the switch requires
a note but cannot decide whether its stated cause is genuinely unexplained.
A deterministic defect therefore still requires the explicit amendment and
exposed-data disposition in protocol section 7. The generic new-directory
suggestion in `_new_directory` is not authorization to evade F15's one-directory
contract. Directory markers also cannot prove that nobody ran an unrecorded
external copy.

Start-marker creation and some preflight failures occur outside the stage's
exception-catching body, and native process termination can bypass Python
exception handling. External launch logs/exit status are consequently required.
A missing end time is unobserved, not zero and not inferred from later waiting.

- Six older dependency files had CRLF differences in the existing checkout;
  this clean Linux checkout matches the registered raw bytes. Registered hashes

  test-portability mismatch. The frozen test is unchanged. This path comparison

The saved F14 Linux record's 78 focused passes and broader legacy PyTorch import
errors remain historical validation, not a full-repository pass or a new F15
result. F15's prescribed primary runtime does not require PyTorch.
